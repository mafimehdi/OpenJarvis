## ۱ 🔴 باگ واحدها — حد ضرر ۱۰۰ برابر کوچک‌تر از مقدار درست

| | |
|---|---|
| حد ضرر اعلامی پنل | `USD SL: base 10.00` |
| حد ضرر واقعی در جدول | **۰.۲۰** |
| مقدار درست | **۲۰.۰۰** (ATR×۴) |

دو مسیر مستقل به همین نتیجه می‌رسند:

**الف) ضرب دوباره در `Point`:**
```
ATR(14) طلا M15 ≈ 5.00
5.00 × 4 × 0.01 = 0.20     ← باگ
5.00 × 4        = 20.00    ← درست
```

**ب) `MathMin` به‌جای `MathMax`:**
```mql4
double sl = MathMin(slFromUsd, atrFloor);   // ❌ کف → سقف
double sl = MathMax(slFromUsd, atrFloor);   // ✅ کف واقعی
```

اصلاح: `GF_SLFloor()` در ماژول.

## ۲ 🔴 اسپرد بزرگ‌تر از حد ضرر

```
اسپرد  = 35 پوینت = 0.35 قیمت
حد ضرر = 20 پوینت = 0.20 قیمت
```

اسپرد **۱۷۵٪** کل بودجه حد ضرر را می‌خورد. بدترین اسپرد پنل (۱۶۰ پوینت)
هشت برابر حد ضرر است.

### چرا بک‌تست «عالی» بود

در Strategy Tester اسپرد یک عدد ثابت و کوچک است. با حد ضرر بیست‌پوینتی:

| | بک‌تست | لایو |
|---|---|---|
| اسپرد | ثابت، کوچک | ۳۵–۱۶۰ پوینت |
| اسپرد نسبت به SL | کوچک | **بزرگ‌تر** |
| نتیجه | SL کم می‌خورد، TP زیاد می‌خورد | پوزیشن فوراً در ضرر |

نسبت ریسک به ریوارد در حالت معیوب **۱:۲۸۰** است — که یعنی حد ضرر عملاً
غیرفعال است. با اصلاح، به **۱:۳** می‌رسد.

اصلاح: `GF_MinStopDistance()` که کف را از
`MathMax(STOPLEVEL, اسپرد × ضریب) + بافر` حساب می‌کند.

> **مرجع:** الگوی `MarketInfo(Symbol(), MODE_STOPLEVEL) * _Point` در
> `PositionSizer/MQL4/Experts/Position Sizer/Position Sizer Trading.mqh:972`

هر ۹ ورود در ثانیه ۰ یا ۱ بعد از مرز M15 — امضای «سیگنال در بستن کندل،

**چرا در بک‌تست دیده نمی‌شود:** با مدل `Open prices only`، `OnTick()` فقط

می‌شود. سیگنال و پر شدن در یک لحظه به نظر می‌رسند — تأخیر نامرئی می‌شود.

اصلاح: `GF_SendStopOrder()` برای ورود با سفارش معلق روی سطح سیگنال.

## ۴ 🟠 حلقه بستن با ایندکس اشتباه

سه سفارش گروه `13:45` **همه روی قیمت 4182.31** بسته شدند، ولی در سه لحظه:

```
733844793  →  13:48:09
733844775  →  13:48:19   (+۱۰ ثانیه)
733844787  →  13:48:24   (+۵ ثانیه)
```

اگر یک TP مشترک فعال شده بود، سرور هر سه را هم‌زمان پر می‌کرد. تأخیر
پله‌ای، امضای کلاسیک حلقه با ایندکس صعودی است:

```mql4
for(int i = 0; i < OrdersTotal(); i++)   // ❌ با هر بستن، ایندکس جابه‌جا می‌شود
```

اصلاح: `GF_CloseAllReverse()` با ایندکس نزولی.

## ۶ 🟠 پارامترهای ناسازگار

| پارامتر | مقدار | مشکل |
|---|---|---|
| `BE at` | `0.0` | با اسپرد ۳۵ پوینتی، پوزیشن بلافاصله سربه‌سر می‌شود |
| `Trail from / Dist` | `1.00$ / 1.00$` | تریل ۱۰۰ پوینتی با SL ۲۰ پوینتی نمی‌خواند |
| `SL modes` | `USD+ATR floor` | منبع باگ واحدها |

**شاهد از جدول:** سودها `+۰.۱۲`، `+۰.۱۶`، `+۰.۰۹`، `+۰.۱۷` دلار بودند —
یعنی پوزیشن‌ها بعد از ۷ تا ۱۷ پوینت بسته شدند، نه ۵۶ پوینت (تارگت).
این امضای دقیق BE روی صفر است.

اصلاح: `GF_BreakEvenDistance()` = `max(اسپرد + بافر, کف ایمنی)`.

## ۷ 🔴 `OrderSend` بدون بررسی خطا — استنباطی

بدون سورس قابل تأیید نیست، ولی از آنجا که اکسپرت در لایو **معامله می‌کند**،
این مورد احتمالاً درست است اما نمی‌توانم قطعی بگویم. بااین‌حال بررسی کنید:

```mql4
// ❌
OrderSend(Symbol(), OP_BUY, lots, Ask, slip, sl, tp, "GF63", Magic);

// ✅ الگوی مرجع
int ticket = OrderSend(...);
if(ticket == -1)
{
   int error = GetLastError();
   Print("Execution failed: ", IntegerToString(error), " - ",
         ErrorDescription(error), ".");
}
```

> **مرجع:** `PositionSizer/MQL4/Experts/Position Sizer/Position Sizer Trading.mqh:607`

## ۸ 🟡 موارد تأییدنشده

- **جهت حد ضرر** — در جدول، S/L در سفارش‌های BUY بالاتر از قیمت ورود و در
  SELL پایین‌تر خوانده می‌شود. این برای هر دو جهت **سمت اشتباه** است. چون
  MT4 چنین سفارشی را با خطای ۱۳۰ رد می‌کند و این پوزیشن‌ها دقیقه‌ها زنده
  ماندند، احتمالاً منبع **خطای خواندن اسکرین‌شات کم‌کیفیت** است. ولی چون
  خطرش فاجعه‌بار است، باید در کد تأیید شود.
- **شمارنده‌های پنل** (`Trades: 9, W:7 L:2`) — تطابق با تاریخچه واقعی حساب.
- **`OnDeinit`** — آزادسازی آبجکت‌ها.
- **محاسبه ATR روی `shift` درست** و محافظت از تقسیم بر صفر.
